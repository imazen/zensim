## bigcodec decision — STOP local, run the zenfleet wave (bf944)

**Local ETA ≫ the ~6 h bar → the plan's fleet branch fires.** Basis
(measured, this box, this extractor build): sustained foldapp2 extraction is
~61 pairs/s wall at the run-heavy cap (dial grid: 6,487 pairs / 106 s;
legs: same rate as the 924-era W1 run). The bigcodec wave is **5,742,660
records** (`tbig_924_full` row count; 490,173 fleet job cells) →
5,742,660 / 61 ≈ **26.1 h of extraction compute alone**, before the data
plane (the bf-wave encodes live in R2 TAR archives addressed by
`variant_index.tsv` byte ranges — a data plane only the zenfleet worker
implements; ~570 GB equivalent). The 924 precedent: the identical-shape
bf924 wave took **~7.5 h on the household fleet** (tower zen924-basement +
lianli + jason; DATA_PROVENANCE "bf924" section), extraction-complete with
gap 0. Rebuilding that data plane as a local one-off is exactly the
hand-rolled-fleet anti-pattern the workspace bans.

**Recommended bf944 recipe (extend the owners, do not fork):**
1. zenmetrics: add metric string **`zensim-foldapp2`** to the jobexec
   executor (the `zensim-foldapp` handler + `append2_block: true` at 944),
   bump the zensim git dep to ≥ `ec3bdd6acd48`, add the parity test
   (extend `folded924_matches_driver_args`), build + push the worker image
   LOCALLY (feedback_build_push_images_locally) as a new TAG of
   `zenfleet-worker` (never a new package name).
2. `declare_bf944.py` cloning the drained `bf924-*` manifests with
   `kind.metrics -> ["zensim-foldapp2"]` + a separate pool
   `jobs/_pool944/runlist.tsv` (the same two-layer stale-image safety
   declare_bf924.py used: new pool URI + new metric string).
3. Household fleet run (~7.5 h at 924-era scale; +1.8 % for append2 per the
   V5 perf gate), ledger snapshots, then
   `fleet_blob_assemble_944.py` (N_FEAT=944, REGIME="folded720append2") →
   `tbig_join_944.py` for the 21 views → `gate_backfill944.py` per view vs
   the 924 views (the gate tool ships in this wave and is view-agnostic).

The legs + kadis + grids deliverable stands alone; nothing below depends on
bigcodec.
