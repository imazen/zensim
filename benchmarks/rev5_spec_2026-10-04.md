# Rev5 — f32 local-window arithmetic plus the value-changing fixes, for by_v2fy (spec, 2026-10-04)

Owner decisions, 2026-10-04 (verbatim): "should we do a rev5 version of by_v2fy that tests f32 leaves and fixes the other bugs, and
targets parity with simd rather than scalar, for speed?" then, after the proposal: "appy your ideas and bugfixes, dont care about
scalar perf or wasm, fma is great if fast." That approves a new `FormulaRevision::Rev5` variant (the enum is `#[non_exhaustive]`;
CHANGELOG and API snapshot move together), retraining by_v2fy at Rev5, and dropping speed requirements for the scalar and wasm tiers.

Registered before any Rev5 code exists. Evidence it rests on: `costpot_2026-10-03.timing.tsv` (by_v2fy 1 MP score Rev4 27.9 ms,
Rev3 23.4 ms; prepared map Rev4 70.3, Rev3 73.2), `kernopt2_WORKLOG.md` (final Rev4 split: box_blur_v_copy 18.8 %, vblur_ssim
canon64 17.4 %, rec64_rows8x8 16.1 %, dense canon64 13.1 %, gradient 7.3 %, memset 5.6 %, box_blur_h 4.7 %, srgb_xyb 4.5 %),
`featacc_WORKLOG.md` (f32 storage of the sliding running sum is the dominant structured error; f64 sliding ≈ exact; element
precision bounds the rest; `ssim_dev4` raw-moment cancellation).

## 1. Scope

* `FormulaRevision::Rev5`, computed for the **v1 basic (IDs 0–227) and v2 (372–719) families only** — the families by_v2fy reads
  (its 420 IDs: `costset2_2026-10-03.candidate_ids.json`), so v2 + basic is also servable at Rev5 as a comparison arm. A plan or bake
  that reads any other family at Rev5 is refused with an explicit error; nothing is computed at a lower revision behind its back.
* Same process model as Rev4: `ZENSIM_FORMULA_REV=5`, and cross-revision mixes are refused (`ssim_form::refuse_rev4_mix` pattern).
* Rev1–Rev4 outputs stay byte-identical (every stored table stays reproducible from code).

## 2. Arithmetic

* **A1 Local blur windows.** The 11-tap box (`BLUR_RADIUS = 5`), horizontal and vertical, is summed **per output in f32 over its
  own 11 inputs in a fixed pair tree** (for example s2 = x[i]+x[i+1], s4 = s2[i]+s2[i+2], s8 = s4[i]+s4[i+4],
  w = s8[i]+s2[i+8]+x[i+10]), with production's mirror padding (`tap_mirror`). No running-sum recurrence: an output depends only on
  its window, so rounding cannot travel along a row or strip. The fused SSIM planes (µx, µy, σxx, σyy, σxy inputs) use the same tree.
* **A2 Lanes.** Pools and accumulators use 16 virtual f32 lanes (AVX-512 native; AVX2 and NEON run the same lane order in 2 and 4
  steps) and one fixed pairwise reduce tree. Accumulator precision (f32 lanes or f64 lanes) is chosen per family by measurement
  against `exact` and recorded; either way the order is fixed.
* **A3 FMA.** Fused multiply-add is allowed wherever it is faster. Every tier evaluates the same fused expression; scalar and wasm use
  a correctly rounded fused operation (slow is acceptable there). Exception: A3 must not break F2's identity exactness.
* **A4 Elements** stay f32 (as at Rev4).
* **A5 Copies.** The Rev5 path removes avoidable plane copies and zero fills (`box_blur_v_copy`, `memset` in the Rev4 profile).

## 3. Value-changing fixes

* **F1 Stable moments.** `ssim_dev2` / `ssim_dev4` (and every other raw-power-sum → central-moment conversion in the two
  families) are computed from block-local central moments merged with the Chan/Pébay pairwise formulas in a fixed order. No
  `raw4 − 4µ·raw3 + 6µ²·raw2 − 3µ⁴` expansion. Test: constant-plus-small-noise inputs and the FEATACC 17×9 crop match a two-pass f64
  reference within 1e-6 relative (the crop must give the positive ~3.76e-4, not 0).
* **F2 Identity exactness and one convention.** For bitwise-identical inputs every `Form::Difference` slot is exactly 0.0 and every
  `Form::Similarity` slot exactly its identity value, on every tier, in both `research::extract` and the production walk;
  `Form::ReferenceOnly` slots carry their computed values. `BakeScorer::compute` keeps the score short-circuit (100) but returns the
  same feature vector as `research::extract` at Rev5. Symmetric pair terms must be written so equal inputs give exactly equal
  numerator and denominator (FMA placement included). `feature_invariants` gains a Rev5 test with a zero residue bar for these
  families.
* **F3 Carried Rev4 fixes:** the XYB body/tail tier identity and the `tailhist` sign-bit fold stay in force.
* **F4 Docs:** `PJND_FRAGILITY`'s F15 note ("should be 0") is corrected: the slot is `Form::ReferenceOnly`.

## 4. Steering

`prepare_steering` serves Rev5 bakes. The neighbour-exact engine (`local_refine`, NEIGHSTEER) either replays Rev5 exactly — with
local windows its dependency cone shrinks to the window halo — or refuses Rev5 explicitly. Never a silent approximation.

## 5. Implementation gates (the lane)

* Tier bit-parity at Rev5 on v4x, v4, v3, scalar and wasm128 (aarch64 NEON if a runner is reachable; otherwise say so).
* F1 and F2 tests; Rev1–Rev4 byte identity on the existing tier-audit pairs and the steering identity panels.
* Full release test suite, CI-exact clippy, feature-permutation cells, `api-doc-check` with the Rev5 variant (CHANGELOG + snapshot).
* Accuracy vs `exact` per family on the FEATACC pairs: no family worse than Rev3's f32 era.
* Speed (zenbench, interleaved, pinned single thread, quiet box): by_v2fy score and prepared map at 64², 256², 1 MP and 4 MP on v4x
  and v3, against Rev4 and Rev3, fixed + per-pixel fit. **Target** (not a pass condition): score ≥ 15 % faster than Rev4 at 1 MP on
  v4x. Scalar and wasm are measured for correctness only.

## Addendum A (2026-10-04 11:50 UTC) — extreme speed, zero unnecessary work

Owner, verbatim: "Let's get our new model optimized so it doesn't do any unnecessary work", then "Extreme speed. Eval as a jxl
and zenjpeg steering map and zqi". Speed becomes the primary objective after correctness; the §5 15 % figure is withdrawn as a
target (the lane iterates until no waste remains and three consecutive kernel attempts each gain < 2 %).

Measured waste on the Rev4 by_v2fy path (perf, 1 MP, single thread): the v1 basic fold and the v2 path V-blur the same
H-blurred planes separately (fused V-blur+SSIM 14.8 % plus four plain V sweeps 12.6 %), duplicate activity chains, per-call
scratch allocation and zero fill (memset 6.2 %), copies (memmove 3.5 %), full-resolution X/B planes stored only to feed the 2×2
downscale although by_v2fy reads no scale-0 X/B (sRGB→XYB 7.3 %), and a per-image XYB mean-offset pass (3.5 %). Rev5 must
compute each plane once, reuse scratch across calls, fuse conversion with downscaling where scale 0 is unread, and compute no
family or channel-scale the bake does not read (by_v2fy reads no peaks and no scale-0 X/B). The XYB mean offset may be
redefined at Rev5 if the change is measured against `exact` and recorded (a value change, allowed in a formula revision).
A work-census gate proves the absence of waste.

Evaluation adds (coordinator, after landing): steering maps for JXL (jxl-encoder), zenjpeg and zqi lossy encodes — per-block
quality-swap allocation (map-guided vs oracle vs random at equal block share), judged by zensim and independently by
SSIMULACRA2 and butteraugli — on top of the broad-96 / owner-12 / KADID JPEG 8×8 panels, CHROMAQ and E24.
