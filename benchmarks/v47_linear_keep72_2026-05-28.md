# v47-linear-keep72 — soft-monotone-keep-72 trainer mode (#39 followup #2)

User (2026-05-27): "do 1 2 and 3 first, let's push this a good as it can
get". Item #2 = trainer mode that strictly enforces the 300 sign-safe
features at W≥0 while keeping the 72 unpinned ("sign-flip") features
FREE. Goal: close the gap between MVP-Python's CID22 0.824 SROCC and
the Rust trainer's soft-only strict-drop CID22 0.658.

## What landed

New trainer flag `--monotone-pin-during-training` (TOML field
`monotone_pin_during_training`):

- **300 pinned features**: HARD-projected to `≥0` after every Adam step
  (matches the final bake projection exactly — no train/bake sign drift).
- **72 unpinned features**: stay FREE throughout (no penalty, no
  projection). `monotone_strict`'s "drop unpinned" branch is SUPPRESSED
  when this flag is set.
- Recipe: `zensim/weights/manifests/v47_linear_keep72.toml`.
- Bake: `/mnt/v/output/zensim/bakes/v47_linear_keep72_2026-05-28.bin`
  (15.8 KB, same size class as the prior strict-mode shipped MVP).

## Honest verdict — partial

The mode WORKS (the constraint is enforced; the 72 free features are
kept; training converged cleanly to val_srocc=0.9045 — slightly above
strict's 0.8862). But it doesn't replicate MVP-Python's CID22 win:

- **Adam + soft penalty ≠ BVLS.** MVP's LS solver finds a sparse global
  optimum (only 86/372 active weights — the BVLS bounds force exact
  zeros at the constraint boundary). The Rust Adam optimizer ends up
  with non-zero weights on all 72 free features, learning training-set
  noise that doesn't transfer to CID22 held-out.
- **Free unpinned features learn training-set noise.** Hidden=8 with
  rank head + per-sample-α gates is already a richer model than the
  pure linear MVP. The 72 free features fit the safesyn + cid22_train
  joint training noise, and this overfits on held-out CID22.
- **The TID + AIC-4 wins are small but real.** Analytic-distortion
  corpora benefit from the 72 sign-flip features (they encode JPEG
  artifact-specific signal that the 300 sign-safe features miss).

## What this means for the v47-linear ship recipe

| consideration | result |
|---|---|
| Strict (drop 72) is the better RECIPE for CID22 codec rank | CONFIRMED |
| Keep-72 mode is ORTHOGONALLY useful for KADID-style analytic | CONFIRMED (TID +0.013, AIC-4 +0.015) |
| Closes the Python-MVP gap | NO (CID22 went DOWN, not up) |
| Should we ship a separate `linear-keep72` sibling? | NOT YET — wait for L1-sparse follow-up that mimics BVLS exactly |

## Follow-up to close the actual MVP gap

Two paths to try:

1. **Add L1 sparsity on the 72 free features only.** A small λ that
   nudges them to exactly zero unless they materially help. This
   mimics BVLS's "stay at the boundary unless needed" behavior. The
   risk: L1 + soft penalty + hard projection may compound into
   convergence instability — needs careful λ tuning.
2. **Use BVLS for the LINEAR case directly.** When `hidden=1` AND
   `leaky_alpha=1.0` AND no nonlinear ops on the path, the
   feature→score chain IS a linear LS problem — solve with BVLS in
   Rust (the `lsq_linear` algorithm has a clean reimplementation in
   `nalgebra-lapack` or as a small standalone). Skip Adam entirely
   for that case.

Both are larger follow-ups; not blockers for the trail decision.

## Methodology

- Trainer: `zensim-validate/target/release/zensim_mlp_train --manifest zensim/weights/manifests/v47_linear_keep72.toml`
- Hyperparams: hidden=8, leaky_alpha=1.0, epochs=200, lr=0.001, l2=1e-4, mse=0.6, ranknet=0.6, monotone_cbc=true, monotone_pin_during_training=true, monotone_strict=false, qat_fine_tune_epochs=0, out_dtype=f32
- Training groups: safesyn (196k) + cid22_train (17.6k) + kadid (10.1k) + tid (3k). konjnd_dense INTENTIONALLY excluded.
- Output spline: PCHIP fit on the multiband_anchor's 2000 rows; pred range [47.66, 48.73] → target [0, 97.4].
- Bake: 15,771 bytes. f32 weights, monotone-by-construction (300 pinned ≥0, 72 free, rank_w ≤0, α≡1).
- Best val SROCC (geomean3): 0.9045 at epoch ~150.
