## TL;DR

V_22-CVVDP trades V_22-IW v2's KADID/TID multi-corpus IWSSIM training
for a strictly better compression-corpora result. **CID22 SROCC +0.041,
AIC-3 SROCC +0.042, KonJND SROCC +0.165 vs V_22-IW v2 PreviewV0_5.**
KADID/TID lose by 0.10–0.12 SROCC because they're non-compression
distortions and V_22-IW v2 also trains on their human-MOS signal,
which V_22-CVVDP does not directly model.

Per user's Z-RMSE + codec-focused lens, V_22-CVVDP is the better ship
candidate.

## (a) Architecture

- 372 input features × 128 hidden × 1 output, LeakyReLU α=0.01
- Output is `cvvdp_log_norm` — log-transformed CVVDP JOD score in
  [0, 100]: `cvvdp_log_norm = (-log(10 - cvvdp + 1e-6) - lo) / (hi - lo)
  × 100` where (lo, hi) are min/max of `-log(10 - cvvdp + 1e-6)`
  observed in the training set
- Parameter count: 372 × 128 + 128 + 128 + 1 = 47,873 weights at f32
  = 191,492 bytes raw + ZNPR v3 header & metadata
- Bake size: 200,984 bytes (200 KB)
- md5: `0be25125f924ebc68cbcc3462e39bffc`

## (b) Training command + hyperparameters

```sh
./target/release/zensim_mlp_train \
  --group safesyn:/mnt/v/zen/zensim-training/2026-05-17-cvvdp/safesyn_features_iwssim_cvvdp_372col.parquet:1.0:0.0 \
  --group kadid:/mnt/v/zen/zensim-training/2026-05-17-cvvdp/kadid_features_iwssim_cvvdp_372col.parquet:0.3:1.0 \
  --group tid:/mnt/v/zen/zensim-training/2026-05-17-cvvdp/tid_features_iwssim_cvvdp_372col.parquet:0.3:1.0 \
  --target-column cvvdp_log_norm --target-scale 1.0 \
  --hidden 128 --epochs 300 --pairs-per-epoch 50000 \
  --lr 1e-3 --l2 1e-5 --leaky-alpha 0.01 --val-policy min --seed 3 \
  --log-every 60 --early-stop-patience 50 --max-features 372 \
  --auto-transforms benchmarks/v0_20_feature_transform_greedy_screen_2026-05-15.tsv \
  --auto-transforms-min-lift 0.05 \
  --minibatch-size 256 --pwrc-pair-weight --norm-in-norm-weight 0.1 \
  --out /mnt/v/zen/zensim-eval/cvvdp_safesyn_2026-05-17/v22cvvdp_full_mc_s3_h128.bin
```

Identical to V_22-IW v2 v3 except: (a) target column is
`cvvdp_log_norm` (not `iwssim_log_norm`), (b) seed=3, (c) input
parquets include the new `cvvdp_score` + `cvvdp_log_norm` columns.

Training time: ~50 sec wall on 16-core Ryzen 9 7950X (300-epoch
schedule with early stop typically firing at ~150-200 epochs).
Best val_mean SROCC = 0.9826.

## (c) Lineage

Single-stage training. No concat / finetune / KD. V_22-CVVDP is NOT
built on top of V_22-IW v2 or PreviewV0_5.

The training-corpus CVVDP scores were generated by:
1. R2 sync of v15r-zenjpeg CVVDP backfill from
   `s3://zentrain/cvvdp-backfill-2026-05-15-half/cvvdp_imazen/` — 711k
   pre-existing CVVDP scores from a vast.ai sweep (May 15-16)
2. Local cvvdp-gpu backfill on the safesyn 196k pairs (2h 50min,
   ~22.6 pairs/sec on CUDA)
3. Local cvvdp-gpu backfill on KADID 10125 pairs (~6 min)
4. Local cvvdp-gpu backfill on TID 3000 pairs after BMP→PNG conversion
   (~70 sec)

All scores merged into the existing 372-feature IW-SSIM training
parquets (which were built per the V_22-IW v2 pipeline) via
`scripts/merge_safesyn_cvvdp.py`.

## (d) Calibration

`cvvdp_log_norm` is min-max-normalized to [0, 100] at training-data
construction time, so the bake's raw output is already approximately
score-shaped. No post-bake affine calibration was applied.

The bake's `feature_transforms` metadata propagates from the trainer
unchanged (uses the v0_20 greedy-screen transforms TSV); runtime
dispatch via `Predictor::predict_transformed` is correct.

## (h) Honest gaps — where V_22-CVVDP is WORSE than V_22-IW v2

**Substantive losses:**
- **KADID aggregate SROCC**: V_22-CVVDP 0.8306 vs V_22-IW v2 0.9506
  (-0.120). KADID has 81 reference images and 25 distortion types
  with 5 severity levels each; the V_22-IW v2 ship explicitly trains
  on these pairs at `train_w=0.3` via the IWSSIM signal, which
  directly teaches the network KADID-specific MOS patterns.
- **TID aggregate SROCC**: V_22-CVVDP 0.8562 vs V_22-IW v2 0.9617
  (-0.106). Same mechanism as KADID.
- **KADID/TID Z-RMSE**: +0.224 / +0.222 — worse calibration on
  these corpora.

**Why ship anyway**: Per CLAUDE.md "Training goals" — the metric is
for **codec quality** decisions. KADID and TID distortions are
~95% non-compression (blur, noise, color shifts, geometric warps);
the SROCC wins by V_22-IW v2 on these corpora overstate its
real-world product value. Per user directive 2026-05-17 to weight
KADID + TID lower than CID22 / AIC-3 / KonJND, V_22-CVVDP is the
strictly better ship under the codec-focused lens.

n-weighted Z-RMSE on compression-focused corpora only
(CID22 + AIC-3 + KonJND):
- V_22-IW v2: (4292×0.569 + 600×0.578 + 1008×0.994) / 5900 = **0.642**
- V_22-CVVDP: (4292×0.515 + 600×0.522 + 1008×0.989) / 5900 = **0.594**
- V_22-CVVDP wins by **0.048** on compression-corpora Z-RMSE.

**Minor gaps**:
- KonJND aggregate SROCC = 0.1950 — still low in absolute terms
  (KonJND's PJND-anchored score axis is fundamentally hard for any
  metric; V_22-IW v2 ship was 0.0303 — V_22-CVVDP is 6.4× better).
- CID22 B9 (n=43) and B3 (n=57) are noisy bands but trend with the
  aggregate.
