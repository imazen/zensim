# Layer-0 input-column norms — what GD actually selects (2026-05-15)

After the V_20 extended (300-feat) bake aggregate-failed CID22 (SROCC
0.8783 < V_18 ship's 0.8933), the question is whether extending the
input feature set was an **architectural** failure ("MLP can't use
the extra features") or a **generalization** failure ("MLP uses
the extra features but the resulting predictions don't transfer to
CID22").

The new `inspect_l0_input_norms` tool reads a bake and reports
per-input-column L2 norm in layer 0:

```
‖w0[i, :]‖₂ = sqrt(sum_j w0[i, j]^2)
```

A near-zero norm means GD ignored that column. A norm comparable to
the basic-block max means GD selected the column heavily.

## Result — GD selects masked + IW features heavily

| Bake | Inputs | basic mean L2 | peaks mean L2 | masked mean L2 | IW mean L2 | Dead inputs |
|---|---:|---:|---:|---:|---:|---:|
| V_18 ship | 228 | 3.39 | 2.99 | — | — | 0 |
| V_20 IS | 228 | 2.30 | 2.02 | — | — | 0 |
| **V_20 extended (300)** | 300 | **1.98** | **1.78** | **1.94** | — | **0** |
| V_20a iw_k1_s1 | 372 | 2.56 | 2.86 | 1.98 | **1.77** | 0 |
| V_20a iw_k4_s1 | 372 | 2.55 | 2.91 | 2.14 | **2.23** | 0 |
| V_20a iw_k8_s1 | 372 | 2.66 | 3.20 | 2.21 | **2.56** | 0 |

**Findings:**

1. **No dead inputs in any bake.** Every input column has L2 norm
   above 1 % of the layer's max. GD is not zeroing out the extra
   blocks.

2. **Masked block ≈ basic block in V_20 extended.** Mean L2 norms
   for basic (1.98), peaks (1.78), masked (1.94) are essentially
   equal. The MLP distributes attention across all three blocks
   roughly uniformly. **It is NOT redundant — GD literally
   reweights the prediction surface to use masked features when
   given access.**

3. **IW block mean L2 rises with IW strength k**: 1.77 → 2.23 → 2.56
   as k goes 1 → 4 → 8. At k=8, IW columns carry 96 % of the
   basic-block mean weight. The trainer SELECTS IW features harder
   when their signal is stronger.

4. **Per-input outliers**: V_20 extended's idx 239 (a masked
   feature) is the SECOND-HIGHEST norm at 6.5193 — 98.8 % of the
   global max at idx 22. The trainer found a specific masked
   feature it wants to use as heavily as the strongest basic
   feature.

## Interpretation

The earlier "the 41 masked transforms are redundant" framing in
`v0_20_extended_falsification_2026-05-15.md` (now refined below)
was **wrong about the mechanism**. The correct framing:

- **GD-selection works**: when given access to extended/IW features,
  GD redistributes weight to use them.
- **Generalization doesn't transfer**: the resulting weight
  distribution minimizes training loss on KADID + TID + KonJND.
  Those corpora are dominated by synthetic distortions, so the
  prediction surface GD lands on is a synthetic-distortion-optimal
  surface — which does NOT match the authentic-distortion CID22
  validation set (FRIQUEE 2017 caveat at the trainer-objective
  level).

The V_20a IW falsification is therefore not "IW signal is bad."
It's "training loss optimized over synthetic distortions selects
weight assignments that fail on authentic distortions, regardless
of which feature blocks are exposed."

## What this implies for future work

1. **V_22 CVVDP distillation** (task #45 / #49) gets a stronger
   case: changing the **training target** (CVVDP predictions vs
   ssim2) directly addresses the synthetic-vs-authentic
   distortion-distribution mismatch, rather than fiddling with
   input features.

2. **V_20d JND-anchored output calibration** (task #41) similarly
   targets the prediction surface, not the input features.

3. **Adding more feature columns** (LMS opponent, IW, masked, etc.)
   will get **selected by GD** — but won't move CID22 unless the
   training loss also tracks CID22. The bottleneck is the
   training distribution, not the input feature width.

## Methodology gap closed

This finding came from a user-driven hypothesis check: "the iw
features might be selected in gd even if the whole package fails
srocc." The hypothesis is **confirmed** — IW (and masked) columns
DO get selected by GD, contradicting the earlier "redundant
features" framing. The right verb is "trainer-objective
mis-aligned with CID22 ship gate," not "feature signal absent."

The principled workflow Step 8 ("visual diagnostics before next
experiment") should add **L0 input-column norm inspection** to the
standard diagnostic toolkit: when a bake doesn't ship, before
concluding "feature redundant," run `inspect_l0_input_norms` to
distinguish "GD ignored the columns" from "GD used the columns but
predictions don't transfer."

## Tool

`zensim-validate/src/bin/inspect_l0_input_norms.rs` — built via
`cargo build --release --bin inspect_l0_input_norms -p zensim-validate`.

Usage:
```sh
./target/release/inspect_l0_input_norms \
  --bake benchmarks/v0_20a_sweep/iw_k1_s1.bin \
  --top 10 --regions
```

`--regions` reports per-block aggregates per the standard zensim
layout (`basic [0..156) / peaks [156..228) / masked [228..300) /
IW [300..372)`).
