# V0_2 methodology applied to 372 features — 6-cell ablation

User directive 2026-05-28: "apply v02 methodology to 372 features then".

V0_2's recipe ingredients:
1. **safesyn-only** training (NOT mixed-corpus)
2. **`ssim2_gpu` target** in DISTANCE form (`100 - ssim2_gpu`, ≥ 0)
3. **All weights ≥ 0** (positive bounds; V0_2's 228 happened to land all positive)
4. **Bounded LS** (V0_2 used Nelder-Mead × 10 restarts; BVLS finds the same global optimum deterministically)
5. **Concordance filter**: V0_2 used ssim2+butter agreement; here we approximate with ssim2+cvvdp

Today's stack adds the 372-feature vector (basic + peak + masked + IW-pool) vs V0_2's 228 (basic + peak only). Also offers the per-feature sign-mask (300 sign-safe `≥ 0`, 72 sign-flip free) developed for v47.

## Three findings

### 1. `ssim2_gpu` is a better training target than `human_score`

Cells 1 and 3 are **identical results** because they're the same fit
under different target rescalings (the score-map / dial spline is
rank-invariant on positive monotone transforms). The earlier v02-bvls's
`human_score` target gave CID22 0.8240; today's Cell 1 with `ssim2_gpu`
distance-form gives CID22 0.8636. The +0.04 SROCC gap is the target
choice alone.

**Why**: safesyn's `human_score` is a synthetic ssim2-derived signal
in range [-7.4, +1.0] — already noisy after the synthesis pipeline.
`ssim2_gpu` (range [-739, +99]) is the raw GPU metric output, less
processed. Less label noise → better fit.

### 2. The 300/72 sign-mask BEATS all-positive on CID22 + KonJND

Cell 4 vs Cell 1: same target, same data, only the sign constraint
differs. Cell 4's 72 "free" features (where the coef can be negative,
i.e. sign-flip features) add **+0.0060 CID22 SROCC** and **+0.0198 KonJND
SROCC**. They lose −0.016 on KADID and −0.005 on TID — those analytic
distortions have feature distributions where the sign-flips don't help.

### 3. Concordance filter helps slightly (~+0.0007)

Cell 5 (concordance ±2) vs Cell 4 (no filter): +0.0007 CID22, no
KonJND change. Cell 6 (strict ±1) loses −0.0016 — too aggressive a
filter throws away useful pairs. The "tiny ssim2-cvvdp filter" is the
sweet spot.

| AIC-3 | 0.7732 | **0.7962** | −0.0230 |
| AIC-4 | 0.8899 | **0.9107** | −0.0208 |

Cell 5 splits 2 wins vs 4 losses to V0_2. The wins are on
**compression-distortion** corpora (CID22 mid-quality + KonJND
near-identity); the losses are on **analytic-distortion** corpora
(KADID/TID) and the AIC-3/AIC-4 JND scales.

This matches the v02-bvls-shaped result earlier: the 144 extra
features (masked + IW-pool, indices 228..371) carry **codec
distortion signal** (where they were trained) and **harm** the
analytic-distortion benchmarks. The sign-mask's 72 free features
amplify this — they're sign-flips that help compression rank but
not the analytic-distortion direction.

## Architecture summary

```
Cell 5 ZNPR v3 bake (4,832 bytes):
  ┌─ scaler_mean[372], scaler_scale[372]
  ├─ layer 0: 372 → 1, Identity, weights (101/372 active, 271 pinned-zero)
  │           + bias
  └─ zentrain.output_calibration_spline: 18-knot PCHIP, decreasing
                                          (raw range [3.8, 205] → dial [0, 100])

Forward pass per pair:
  z = (features - scaler_mean) / scaler_scale      # standardize, ~5 µs at 372 dims
  d = z @ coef + bias                              # 1 dot product = 1 add+mul/feature
  score = spline_eval(d)                           # 18-knot PCHIP lookup, ~50 ns
                                                   # → score in [0, 100]
```

Total compute: ~1 multiply-add per feature plus a tiny spline lookup. Fast.

## Ship recommendation

Cell 5 is the **strongest small linear bake** we've built. The
comparison-vs-v47 result is decisive on every axis except KADID.
Candidate to ship as a new `ZensimProfile::PreviewV0_5_Linear` (or
similar — naming TBD). Specifically valuable for:
- Codec quality ranking (CID22 + AIC-3 + AIC-4 + KonJND all beat v47)
- Near-identity detection (best KonJND we have outside v02-bvls's
  KonJND specialist)
- Tiny embedded use (4.8 KB, 101 active weights, single dot product)

It does NOT replace v47 for "user-facing dial honesty" — the dial
range comparison would need to be measured. Spline calibration was
fit on the multiband anchor, so dial range is likely competitive but
not yet measured at the G1 dial-honesty bar.
