## Scalar cause and first fix

Baseline scalar t8 1920×1080 perf attributes 28.33% of sampled cycles to
`fused_blur_h_ssim_local_general`; its Rev4 horizontal entry accounts for
9.66%. Callgrind confirms 2,665,910,730 instructions (27.41%) in that Rev5
function. Total measured process instructions, including input/model setup:
Rev4 6,051,427,926; Rev5 9,726,429,182. These are profiler observations,
not timing qualification.

The scalar horizontal kernel recalculates the same tap leaves, mirror indices
and fused products in adjacent windows. A 16-slot ring now reuses those leaves,
then executes the identical 11-tap pair tree per output. Scalar vertical blur
resolves eleven row slices once per output row. The radius-zero scalar SSIM
consumer reads the shared vertical value directly, avoiding its one-tap staging
loop and multiplication by one. No window or accumulator order changes.

The new scalar-kernel gate compares every output bit with the untouched general
windows, including narrow mirrored boundaries, signed zeros, identity leaves,
both cross-product forms and ring wraps. It passes. The existing Rev5 full-vector
token-permutation and revision-difference gates pass as well. Resource receipt:
rc=0, 84s, peak-RSS 3.12GiB, min-avail 35302MiB, peak-load 5.82. Full production
parity, all-feature tests and after timings remain pending.

Baseline perf resource receipt: rc=0, 57s, peak-RSS 0.27GiB,
min-avail 37967MiB, peak-load 3.17. Baseline Callgrind/full production parity/
four-cell paired timing receipt: rc=0, 339s, peak-RSS 3.32GiB,
min-avail 34116MiB, peak-load 3.16. All four baseline segments retain 32 clean
rounds through the approved shared-index rule. Their raw paired analyses remain
under `before/timing/`; no after comparison is claimed yet.

## Producer scheduling and SIMD edge fixes

The Rev5 unread-X/B producer converted the source and distorted sides
sequentially. Its two-row conversion calls also pass `parallel=false`, whereas
the Rev4 producer joins the two sides and offers inner row chunks. The
two sides have disjoint rolling planes and chroma scratch. `4b451bfb` joins
them when the caller requests parallel execution; every conversion, downscale
and cached-reference copy keeps its original inputs and order within a side.

Baseline diagnostic phase counters at v4/t8/1920×1080 attribute 8.670 ms
to Rev5 conversion versus 2.321 ms at Rev4 (single cold observations, not
qualified latency). The producer/vector tests pass, and `join/frozen-parity.json`
verifies all 576 observations against baseline, including 384 strict Rev4/Rev5
score-and-420-feature observations. `scalar/frozen-parity.json` independently
verifies the scalar-only candidate before the scheduling change.

The scheduling candidate's four-cell timing retains 32 clean rounds per cell.
These are within-build Rev5 minus Rev4 paired confidence intervals; separate
build observations are not directly paired with each other.

## Vertical-node candidate and remaining producer cause

`d25574de` reuses only existing vertical pair/quad nodes in eight-vector
column tiles. Every cached node has the same two operands and rounding as
its frozen expression. Mirrored rows, the incomplete vector and the final
multiply retain the same arithmetic. Kernel/vector and all-feature tests,
workspace/SPEEDQ clippy and full frozen parity pass. The full collection
resource receipt is rc=0, 761s, peak-RSS 3.32GiB, min-avail 42473MiB,
peak-load 6.68. These four cells are an intermediate candidate, not the

Small-input parity with Rev4 is inconclusive, not established equivalence.
Callgrind scalar process instructions at this stage are Rev4 6,062,893,192,
Rev5 6,423,030,520. Phase diagnostics locate the remaining scalar wall
overhead in conversion: Rev4 9.966 ms, Rev5 31.125 ms. These are single cold
diagnostic observations. The gated paired timing owns the regression claim.
Joining the two sides restored degree two, but Rev5's two-row calls still
ran each side serially. Rev4 also uses the existing 64-row conversion chunks.

The current producer candidate restores those chunks. Each task owns
disjoint Y/coarse-X/coarse-B output slices and two-row X/B scratch. All
fallible allocation occurs before mutating output/cursors; allocation failure
uses the existing serial buffers. Every pointwise conversion still receives
the same two-row subset, absolute row offset and revision, followed by the
same two-row downscale. An odd last row stays in the last chunk, rather than
being lost through a short coarse-plane iterator. The producer gate now
includes cached/uncached and serial/parallel operation, odd last-chunk rows,
and the existing two-row full-resolution chroma storage assertion.

`7b82fe69` caches the SIMD fused square/product leaves in bounded row tiles.
The window still loads the same source/destination leaves and executes the
same fixed tree; no output recurrence or changed FMA expression is used.
Its kernel/vector receipt: rc=0, 24s, peak-RSS 2.73GiB, min-avail 43629MiB,
peak-load 5.00. Producer candidate kernel/vector receipt: rc=0, 69s,
peak-RSS 2.79GiB, min-avail 43498MiB, peak-load 8.90.

binary, profiles and all raw measurements remain recoverable. The final

producer fan-out and all earlier retained fixes.

versus 31.125 ms before row fan-out. This locates the earlier remaining
scalar conversion cost in scheduling rather than changed arithmetic.
