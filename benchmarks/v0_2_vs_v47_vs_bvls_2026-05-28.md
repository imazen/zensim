# V0_2 vs v47 vs v02-bvls — head-to-head on canonical-2026-05-18/val/

User question 2026-05-28: "how does this compare to v02"

V0_2 = the original 228-weight linear-table profile shipped 2026-03
(`ZensimProfile::PreviewV0_2`, `WEIGHTS_PREVIEW_V0_2` in
`zensim/src/profile.rs`). Trained via Nelder-Mead on 218k
concordance-filtered safesyn pairs against `gpu_ssim2`. 127/228 active
weights. Output via fixed score-map `100·exp(-0.18·d^0.7)`.

This is the first time V0_2 has been measured on the full Mohammadi 2025
panel against the new validation corpora (KonJND/AIC-3/AIC-4 weren't in
the original 2026-03 evaluation).

## Where V0_2 loses: the dial

V0_2's score p5..p95 ranges:

- CID22: [34.9, 73.5]
- KADID: [0.5, 68.2]
- TID: [1.1, 62.1]
- KonJND: [37.7, 56.1]
- AIC-3: [32.3, 77.0]
- AIC-4: [38.7, 79.8]

Across all 6 corpora, **V0_2's score sits in the middle of the [0, 100]
dial** — it never reaches the extremes. CODEC_TARGET_GOALS.md's G1
("p5 ≤ 25 AND p95 ≥ 85") FAILS on every corpus. A user typing "score 20"
or "score 90" can't get there — V0_2's dial is compressed.

This is the *only* axis where v47 wins decisively:

- v47 CID22 dial p5..p95: < 25, > 85 (G1 = 1.00 reported)
- v02-bvls CID22 dial: cleaner spline-calibrated dial p5=-4.8, p95=87.4 (G1 = 1.00)

For a user-facing dial metric, the score range matters. V0_2 ranks better
but the dial pins to a narrow band.

## Why does V0_2 do so well on raw SROCC?

The 2026-03 training recipe was specifically tuned for synth→human MOS
ranking, not for codec-target dial use:

1. **Concordance-filtered training corpus.** Only 218k pairs where
   `gpu_ssim2` AND `butteraugli` agree on rank order. This drops noisy
   labels and leaves a clean, generalizable signal. Today's v02-bvls
   uses 226k pairs from 4 different corpora (safesyn + cid22_train +
   kadid + tid), no concordance filter — noisier overall.
2. **Stable single-source target**: `gpu_ssim2` per-pair scores from a
   well-calibrated reference metric. Today's `human_score` columns mix
   MCOS / DMOS / MOS / synth-derived across the 4 corpora — different
   noise floors.
3. **Nelder-Mead + 10 restarts.** Explored the loss landscape better
   than BVLS's greedy bounded LS for this particular feature subset.
   BVLS converges to a global LS optimum but on a different (noisier)
   objective.
4. **228 features instead of 372.** Lower-dimensional model; fewer
   degrees of freedom to overfit to corpus-specific noise. The
   additional 144 features (masked + IW-pool) added in 2026-05+ help
   some bakes (v47 nonlinear) but contribute noise in pure LS.

The 2026-03 + V0_2 result has aged remarkably well.

## Comparison summary

| | V0_2 | v47 strict-QAT (Profile::A) | v02-bvls NO shaping |
|---|---|---|---|
| Architecture | 228 linear w + score map | 372→128→64 MLP + α-head + spline | 372 linear w + PCHIP spline |
| Sign constraints | (Nelder-Mead init produces all ≥0 in practice) | per-feature mask (300 ≥0, 72 dropped) | per-feature mask (300 ≥0, 72 free) |
| Bake size | 228 f64 = 1.8 KB embedded | 27.3 KB ZNPR v3 | 8.6 KB ZNPR v3 |
| Best at | **PURE RANKING** on every corpus except KonJND | **DIAL HONESTY** (G1 = 1.00 across the range) | **KonJND** + tiny bake + KonJND/AIC-3 robustness |
| Worst at | Dial range (G1 = 0 — score clusters mid-band) | KonJND (-0.05 vs V0_2) | Codec rank on KADID/TID |
| Training cost | Hours (Nelder-Mead, 10 restarts) | Minutes (Adam, 200 epochs) + QAT | Seconds (BVLS, deterministic) |
| Training data | 218k concordance-filtered safesyn / ssim2 target | 247k mixed canonical (5 groups) / human_score target | 227k mixed canonical (4 groups) / human_score target |

## What this means for the ship decision

- **V0_2 deserves a second look as a SROCC-best sibling.** It's the
  ranking gold standard at 1.8 KB. The dial is its only weakness.
- **v47 remains the right Profile::A** for the user-facing dial
  ("type a number, get an encode at that quality") because of G1 = 1.00.
- **v02-bvls's value-add is KonJND** (+0.12 over V0_2, +0.18 over v47)
  + 8.6 KB footprint. Niche but real.
- A future zensim release could ship V0_2 as `PreviewV0_2_Rank` (already
  is — it's `ZensimProfile::PreviewV0_2`!) and document explicitly
  "use this for SROCC-honest comparisons; use Profile::A for
  codec-target dials". The dispatch should match use case.

The user originally pivoted to "V0_2 + new features + new datasets +
shaping + BVLS" hoping the combination would beat V0_2. Result: **no, V0_2's
recipe (concordance-filtered training + Nelder-Mead) beats the modern
BVLS + 372-feature combination on raw ranking.** The modern stack wins
only on:

- Dial honesty (v47's PCHIP spline + tanh-pin training)
- KonJND specifically (v02-bvls)
- AIC-3/AIC-4 with shaping (compression specialist trail)

Each is a different sibling profile. V0_2 stays the ranking baseline.

## Reproduction

```python
import numpy as np, pyarrow.parquet as pq
ws = np.loadtxt('/tmp/v0_2_weights.txt')  # extracted from profile.rs WEIGHTS_PREVIEW_V0_2
N_V02 = 228
for v in ["cid22", "kadid", "tid", "konjnd", "aic3", "aic4"]:
    t = pq.read_table(f'/mnt/v/zen/zensim-training/canonical-2026-05-18/val/{v}.parquet',
                      columns=[f"f{i}" for i in range(N_V02)] + ["human_score"])
    X = np.column_stack([np.asarray(t[f"f{i}"].combine_chunks().to_numpy(), dtype=np.float64) for i in range(N_V02)])
    y = np.asarray(t["human_score"].combine_chunks().to_numpy(), dtype=np.float64)
    keep = np.isfinite(y) & np.all(np.isfinite(X), axis=1)
    X, y = X[keep], y[keep]
    dist = X @ ws
    score = 100.0 * np.exp(-0.18 * np.power(np.maximum(dist, 0.0), 0.7))
    from scipy.stats import spearmanr
    print(f"{v}: SROCC={abs(spearmanr(score, y).statistic):.4f}")
```
