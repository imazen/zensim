# STEERAPI — `BakeScorer::prepare_steering` serves v2 + basic bakes

2026-10-02 (Mountain Time), lane `steercheck`. Brief: `~/tmp/zensim-paper/rev4/STEERAPI_brief.md`. Behaviour change only; no public
item added or changed (public-API snapshot check passes). Not a qualification of any model.

## Limits first
* **Exact refused IDs are not named, family ID ranges are.** `ZensimError::ModelLoadFailed` carries a `&'static str`, so the refusal
  names the unsupported *family range* (masked/IW f228-f371, append f720-f923, append2 f924-f943, f944 and above), not each ID. Naming
  every ID needs a new error variant (public API): not done, asked in `STEERAPI_decisions.md`.
* **Append/append2 stay refused** even though the older path computes maps for them: they were not part of the brief and their map
  exactness was not measured. The decision file asks whether to extend the range.
* **HDR sessions still refuse v2** (`prepare_steering_hdr`, SDR-only for v2).
* **Timing is not a reliable measurement:** the box carried fleet load (load average 12-13 at the start of the runs, other cores busy),
  zenbench flagged both runs `UNRELIABLE: too many resource gate waits`, and the 4 MP arms have 25 rounds (< 30) with a wide MAD.
  Descriptive only.
* **The semver check is uninformative here:** `cargo semver-checks -p zensim` compares 0.3.0 against the crates.io 0.2.7 baseline, calls it a
  major change and runs 0 checks (254 skipped). The meaningful gate is `just api-doc-check` (public API surface + docs), which passes.
* Ensemble sessions with v2 members are covered by a score test, not by the 96-case panel for non-ensemble bakes (the broad panel is
  ensembles; the owner cases are single bakes).

## What changed
`prepare_steering_input` (`metric/bake.rs`) no longer refuses reads >= 228 wholesale. It takes the complete served read set
(`consumed_feature_ids()`: active ensemble members, corruption companions, replacement min-max inputs included) and
`steering_support()` accepts exactly f0-f227 and f372-f719 (PJND_FRAGILITY is reference-only, an exact-zero integrand). Any other read
is refused before any pixel work with a static message naming the family range(s); `prepare_steering_hdr` additionally refuses v2.
The session itself is unchanged: `SteeringSession::compute` already called the same `compute_attribution_input` as
`compute_with_ref_and_attribution`, so scores and maps come from one owner, and `compute` still refuses an incomplete refinement set at
call time. Method docs, README and the wave playbook row updated; CHANGELOG `[Unreleased]` entry added.

Per-slot map exactness, measured with the existing `diffmap_block_coherence` diagnostic (`ZENSIM_V2_DIAG`, example-only): the `human-full944-h128-full-s5101` bake (944
