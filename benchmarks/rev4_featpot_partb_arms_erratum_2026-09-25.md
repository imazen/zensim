# Erratum to the Part B arms amendment (2026-09-25) — P3 control construction

**POTENTIAL — ceiling, not a model score.** Refers to `rev4_featpot_partb_arms_amendment_2026-09-25.md` (commit `ff9df1b654c4`, 2026-09-25T16:40:28Z). Written 2026-09-25T16:43:14Z, before any P3 result was read.

The amendment says the P3 control permutes "the gmsbank block and peer pair as **one** block with the same procedure". That is not what the adapter can do consistently with the two registered controls it inherits, and it is corrected here: **the P3 control is the P1 control plus the P2 control, each by its own registered procedure.** The 180 gmsbank columns are permuted jointly within each reference over the non-identical `pair_key`s (identical-pair amendment); the reviewed peer pair (gmsd, gmsm) is permuted jointly at key level over all rows within each reference, as in the registered P2 control (their real values on identical rows, gmsd = 0 and gmsm = 1, are exact computed identity values, not fabricated zeros, and are left unmasked). Both draws use seed 20260923 in that order (gmsbank block first, peer pair second), so the two blocks are permuted independently of each other. Nothing else changes.

Label-free checks behind this note (kadid_train, konfig_val): the peer pair on `pixels_identical` keys is gmsd 0.0 and gmsm 1.0 exactly (39 and 4 keys); every Part B family (C1-C4, csfw, C7, gmsbank) is exactly zero on identical rows before masking, and only restore `mapdev` is nonzero there (7,488 cells = 156 rows x 48 in kadid_train).

**Landing note (2026-09-26; describes implemented behaviour, changes no result).** The identical-pair amendment's zero-mask applies to every added candidate/restore column but **not** to the reviewed P2 peer pair (`gmsd`, `gmsm`; packed `f1124`/`f1125` in arm P3). On `pixels_identical` keys the peer pair keeps its true values, 0.0 and 1.0, exactly as in the P2 arm. The policy is implemented in `restore_data.apply_identical_convention` (the `peer_cols` argument) and recorded in every P3 result receipt as `peer_columns_unmasked`.
