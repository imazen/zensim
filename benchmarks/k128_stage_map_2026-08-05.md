# K128 → extraction-stage map: can a K-small model skip extraction work? (2026-08-05)

Appendix-J follow-up (user: "feature extraction speedups are what matter").
Question: take the frozen K128 subset (`benchmarks/featsub/idx/top128.idx`,
top-128 of 944 by `bake_contrib` mean_abs, 45.3% contribution share) and map
every index to the extraction stages that produce it. If the needed stages
are CONCENTRATED, a skippable-extraction build is worth designing; if
SCATTERED, K-small models cannot speed extraction materially and the idea
closes.

**Verdict: outcome (b) — SCATTERED. Measured skippable ≈ 1.6 ms of the
30.5 ms folded-944 extraction call (≈5%; ≈6.5% in a load-inflated
replicate — both land in the same single-digit band). K128 (and even K64)
touches every (scale × channel) plane cell, so the front-end, pyramid, and
phase-A blur — the dominant costs — cannot lose a single cell. The idea
is closed.**

## 1. Method

- Mapping: `scripts/featsub/k128_stage_map.py` (committed; layout constants
  verified against `zensim/src/feature_v2.rs` at `7577dfa6`) decodes every
  index into (block, scale, channel, local, producing pass). Per-index
  table: `benchmarks/featsub/k128_stage_map_2026-08-05.tsv`.
- Pass attribution follows the accumulator that supplies each slot
  (`finish_channel_scale` / `finish_append` / append2 finalize):
  `v1fold` = `fold_v1_basic_bands`; `dense` = `dense_block_kernel`;
  `grad` = `gradient_block_kernel` (+ BANDVIS lanes on Y);
  `block` = the sparse blockiness kernel; `append` = `append_block_kernel`.
  (`GMS_DEV2`/`GRAD_SRC_MEAN` sit in the append LAYOUT but are grad-pass
  products; `ART_DEV2`/`DET_DEV2` need dense first moments + append second
  moments — attributed to append, the marginal pass.)
- Cost: pass marginals measured by toggle deltas on the CANONICAL streaming
  folded walk, two instruments:
  1. `v2_stage_profile` bench, new `folded_stage_{576,1024}` groups
     (zenbench paired/interleaved, serial, city.png) — the standing
     quiet-box instrument. On THIS session's box (5 concurrent agent
     lanes, load avg 22-27 on 28 cores) zenbench's resource gate
     discarded 120/124 rounds as noisy and the kept-4-round CIs crossed
     zero — recorded, not used.
  2. `fused944_probe` with the new `ZENSIM_FOLDSTAGE=only` mode
     (interleaved medians over the same 5 toggle arms, 82 samples/arm,
     576² textured synthetic, serial — the exact appendix-N methodology
     and fixture that produced the registered 19.5/25.6 ms references).
     This is the measurement used below.
  Within-pass per-cell costs are apportioned by pixel share (scale s
  carries 4^-s of base pixels; s0 ≈ 75%).

## 2. What K128 is made of

Block membership: 41 v1-fold + 62 v2-348 + 23 append-204 + 2 append2
(+ 0 from the f156–371 structural zeros — consistency check passes).
Channels: Y 66, X 35, B 27. Scales: s0 67, s1 32, s2 14, s3 15.
Passes: v1fold 41, dense 36, grad 29, block 10, append 12.

Notable: **10 of the vector's 12 BLOCKINESS slots are in the top-128** —
blockiness is heavily over-represented in contribution mass. The 2 append2
members are `BANDVIS_GAIN/LOSS` at scale 0 only.

## 3. Coverage — the concentration test

Grid = (pass × scale × channel), 59 active cells (append B@s0 is already
skipped by `APPEND_SKIP_B_SCALE0`). **K128 touches 42 of 59.** Untouched:

| pass | untouched cells | pixel share of the pass |
|---|---|---|
| append | (2,X) (2,Y) (2,B) (3,X) (3,Y) (3,B) | 7.85% |
| block | (0,B) (1,B) | 31.37% |
| dense | (2,B) (3,X) (3,Y) (3,B) | 2.75% |
| grad | (2,B) (3,X) (3,Y) | 2.35% |
| v1fold | (2,B) (2,X) | 3.14% |

The decisive facts:

1. **All 12 (scale, channel) cells carry at least one K128 feature** — so
   the XYB front-end, the full 4-scale pyramid on all 3 channels, and the
   phase-A H/V blur planes for every cell stay mandatory. (K64 also
   touches all 12 — scattered all the way down; `top64.idx` run of the
   same script.)
2. **At scale 0 — ~75% of all pixel work — every pass×channel cell K128
   could use is used**, except blockiness on B. The skippable cells sit
   almost entirely at scales 2–3 (1/16 and 1/64 of pixels).
3. The only pass skippable at meaningful pixel share is **blockiness on
   B at scales 0–1** (31% of a SPARSE 8-px-lattice kernel — the cheapest
   pass per pixel to begin with).

## 4. Measured pass marginals

576², `ZENSIM_FOLDSTAGE=only fused944_probe 576 41` (82 interleaved
samples/arm, medians; primary run taken in the session's lowest-load
window):

| arm | median ms | marginal |
|---|--:|---|
| folded720 | 25.07 | — |
| folded924 (+append) | 27.68 | **append pass = 2.62 ms** (kernel + `bs2` blur) |
| folded944 (+append2) | 30.50 | **append2/BANDVIS marginal = 2.81 ms** |
| folded944 −gradient | 25.64 | grad@944 = 4.86 ms ⇒ **grad-base ≈ 2.05 ms** (4.86 − the 2.81 BANDVIS share that rides inside the grad kernel) |
| folded944 −blockiness | 28.47 | **block pass = 2.03 ms** |

Internal-consistency check (why this run is trusted): the independent
component model core(20.99) + grad-base(2.05) + block(2.03) [+ append
2.62] [+ bandvis 2.81] predicts 27.77 / 30.58 for the 924/944 arms vs
27.68 / 30.50 measured — closes to 0.1 ms. Replicates: a load-inflated
repeat (load avg 25.5) gave proportionally larger marginals (5.85 / 3.11
/ 2.34 / 4.62 on a 41.8 ms call) and the SAME skippable fraction (§5); a
fully saturated repeat (load ≥ 27) and both 1024² attempts failed the
consistency check (arms crossing, one negative marginal) and are
disqualified — recorded in `~/tmp` logs and reproducible only on a quiet
box via the committed zenbench groups. No 1024 scaling claim is made
(NEVER-EXTRAPOLATE).

## 5. The skippable-fraction arithmetic

skip_ms ≈ 7.85%·M_append + 31.4%·M_block + 2.35%·M_gradbase +
24.7%·M_bandvis + [core-pass residuals]:

| term | ms |
|---|--:|
| append kernel @ scales 2-3, all ch | 7.85% × 2.62 = **0.21** |
| blockiness @ (0,B) + (1,B) | 31.4% × 2.03 = **0.64** |
| grad-base @ (2,B),(3,X),(3,Y) | 2.35% × 2.05 = **0.05** |
| BANDVIS lanes @ scales 1-3 (keep s0) | 24.7% × 2.81 = **0.69** |
| core residuals (dense 2.75%, v1fold 3.14%, V-blur at 3 cells) | not toggleable; bounded ≲ 0.4 |
| **total** | **≈ 1.6 ms (≲ 2.0 with residual bound) of 30.50 = 5.2-6.5%** |

(The load-inflated replicate gives 2.73 ms of 41.8 = 6.5% — the fraction
is stable across load regimes because marginals and total inflate
together.)

## 6. Registered outcome

**(b) — scattered.** A K128-restricted extractor would still run the
front-end, the full pyramid, all phase-A blur planes, and the dense +
gradient + v1fold passes at full resolution on all three channels. The
skippable work is confined to coarse scales and the sparse blockiness
kernel — measured low-single-digit percent of the compare. K-small models
do not unlock extraction speedups; extraction perf work should continue on
the appendix-P levers (f32 pass-B, stale single-pass, in-kernel fusion)
instead. Context: K128 is also not profile-neutral as a MODEL (appendix
J.R2: KonJND +0.055 but cid22/csiq/live regress outside noise), so nothing
ships on it anyway.

The two actionable crumbs, both sub-ms and neither worth a regime event:
blockiness on B at scales 0-1 (no top-128 mass, ~0.64 ms) and the BANDVIS
lanes at scales 1-3 (~0.69 ms — but the per-scale BANDVIS response CURVE
is the documented consumer contract, so dropping scales is a feature
change, not a free perf win).

## Reproduce

```sh
python3 scripts/featsub/k128_stage_map.py benchmarks/featsub/idx/top128.idx \
  --ranked benchmarks/featsub/idx/ranked.tsv
# pass marginals (medians instrument; quiet box preferred):
ZENSIM_FOLDSTAGE=only cargo run --release -p zensim \
  --features custom-profiles,feature-regime-v2 \
  --example fused944_probe -- 576 41
# standing zenbench instrument (needs a quiet box — its resource gate
# discards load-contaminated rounds):
cargo bench -p zensim --features training,feature-regime-v2 \
  --bench v2_stage_profile -- --group=folded_stage_576x576
```
