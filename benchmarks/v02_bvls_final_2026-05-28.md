User pivot 2026-05-28 ("look at V0_2 trainer with new features/data sets/
shaping/BVLS"): V0_2 was 228 features + Nelder-Mead + 127 active linear
weights → CID22 0.867. Today we have 372 features + Yeo-Johnson/Winsor/
SignedCbrt/QuantileBins shaping TSV + canonical-2026-05-21 dataset + BVLS
bounded LS solver. This combines all of them.

## What the experiments confirm / falsify

1. **BVLS with bounds enforced GLOBALLY (Python's `lsq_linear`) >> Adam
   with sign-mask soft penalty.** v47-linear's h=8 strict-mode Adam path
   gave CID22 0.632; the BVLS path on the SAME data gives 0.824 (+0.19).
   The Adam path's soft penalty + projection-at-bake creates a train/bake
   sign-drift that the bounded LS doesn't have.
2. **Shaping is a safesyn-specialized lift, not a universal one.** It
   adds +0.10 on AIC-3 + AIC-4 (compression corpora) but costs
   −0.13 KADID, −0.08 TID, −0.52 KonJND. Shaping was screened on
   safesyn → it's tuned to that corpus's distortion distribution.
3. **Higher cid22_train weight HURTS held-out CID22 SROCC.** cid22_train_norm
   is a TRAINING-only subset (disjoint from the 49-ref validation set)
   — its signal saturates the linear projection's capacity, and further
   weight amplifies cid22_train-specific noise that doesn't transfer.
   Default weight 1.5 is near-optimal for the held-out CID22.
4. **Adding konjnd-dense-norm as a training group BREAKS KonJND
   validation.** The training parquet's `human_score` polarity does NOT
   match the validation `human_score`. SROCC flipped sign: +0.594 →
   −0.578. Don't include this group without first re-investigating the
   polarity convention. (Possibly fixable; not pursued today.)
5. **The BVLS linear path PRESERVES KonJND signal that v47's MLP destroys.**
   v47 KonJND 0.418 vs BVLS 0.594 — a +0.176 gain. v47's f16+zerobias
   packing removes the fine-weight precision PJND discrimination needs;
   linear-with-bias has nothing to quantize away.

## Shipping recommendation

Both variants are viable as `ZensimProfile` SIBLINGS:

### `v02-bvls NO shaping` (recommended for ship as new sibling)

- **8.6 KB** (3.2× smaller than v47's 27 KB)
- **Balanced**: −0.04 CID22 vs v47, −0.04 KADID, −0.06 TID
- **Best KonJND** of any zensim profile we've shipped: 0.594
  (v47: 0.418, V0_4: 0.418, V0_2: ~0.65)
- 86/372 active weights (sparse, interpretable)
- Clean dial: p5=−4.8, p95=87.4 (G1 score 1.00)
- Pure linear: forward pass is a single `dot · scaler` per pair
- Use case: **balanced linear sibling** — fast, small, KonJND-strong,
  graceful when used for image-engine-error detection / regression
  gating.

### `v02-bvls WITH shaping` (compression-corpus specialist)

- **19.4 KB**
- Best AIC-3 (0.846 vs v47's 0.768; +0.078)
- Best AIC-4 (0.897 vs 0.885; +0.012)
- CID22 tied (0.828)
- KADID/TID/KonJND broken
- Use case: codec-quality A/B comparisons where only compression
  distortions matter.

## Why I don't recommend replacing Profile::A

v47 wins:
- Overall geomean (KADID/TID held up; bvls drops these)
- Compression CID22 + AIC-4 by ~0.04 / ~0.09

v47 loses to bvls:
- KonJND by 0.176
- Bake size by 3.2×

For Profile::A as the "general-purpose codec metric", v47 remains the
right choice. The BVLS variants are sibling-shaped, not a Profile::A
replacement.

## What the V0_2 lineage taught us (now newly clear)

V0_2 was a linear model with non-negative weights + a fixed score
mapping `100·exp(-0.18·d^0.7)`. Its 0.867 CID22 SROCC was achieved
*without* per-feature shaping. The new BVLS path on the larger feature
set lands ~0.04 below V0_2 because:

- V0_2 trained on synthetic-only (218k concordant) + a different
  target (`gpu_ssim2`-derived distance).
- Today's BVLS trains on 4 mixed corpora targeting `human_score`.

The "with shaping" CID22 0.828 ≈ V0_2's 0.867 minus ~0.04 — actually
**close** to V0_2 quality. The point of this experiment is not to beat
V0_2; it's to add the modern-corpus diversity without losing more than
a sliver of CID22 quality, while gaining KonJND + AIC-3 robustness.

## Decision tree for the user

```
Use case                                  → Pick
----------------------------------------------- ----
General codec metric, dial-honest         → v47 strict-QAT (current Profile::A)
Image-engine errors / regression gating   → v02-bvls no-shaping
Near-identity / visually-lossless detect  → v02-bvls no-shaping
Compression A/B on AIC-3/AIC-4 corpora    → v02-bvls with shaping
Tiny / interpretable / sparse weights     → v02-bvls no-shaping (8.6 KB, 86 active)
```

## Reproduction (single command)

```bash
python3 scripts/v_next/train_v02_bvls_shaped.py --no-shaping \
  --out /tmp/v02_bvls.bin
./target/release/bake_verdict --bake /tmp/v02_bvls.bin --output /tmp/verdict.md
```

The Python pipeline:
1. Reads the canonical training parquets (~30 sec).
2. Computes scaler + BVLS fit on 226k rows × 372 features (~5 sec).
3. Fits PCHIP spline on anchor (~1 sec).
4. Emits ZNPR v3 JSON + shells to `zenpredict-bake` (~2 sec).
5. Total: ~40 sec on a 7950X.

Verdict via `bake_verdict` (~10 sec, deterministic).
