# COSTSET3 — remove the prepared session's second v1 walk (2026-10-03)

Base: zensim main `5fefafc5` (COSTSET2). Lane bookmark `quarantine/claude/steercheck`, local only, never pushed.

## What changed

`Fused944Session::planned_features` (`zensim/src/attribution.rs`). For a v2-bearing plan the prepared session used to
(1) run the folded v2 walk **with its own v1 fold** (`compute.v1_basic = true`), then (2) in
`attribution_from_retention_binned` find `session.basic.result == None` and run the full fused v1 walk **again** to build
the basic map (57-59 ms at 1 MP, vs 8.8 ms when a basic walk's results are reused).

Now, when the plan is v2-bearing, SDR, has no sampling, `free_extras == Off` and `v1_pools` is `Off` or `Peaks`:

1. the v1 attr-planes streaming walk (the route basic-only plans already use) runs first and fills `session.basic`
   (retained planes, `result`) — **the basic map's accumulation order is untouched**: it is the same walk, same code;
2. the folded v2 walk runs with `v1_basic = false` on a copy of the plan (`fold_v1 = false`: no `fold_v1_basic_bands`, no v1
   accumulation, compact output starting at the v2 block);
3. the served row is `[372 v1 slots from walk 1][v2 walk output]`. Walk 1 supplies f0-155 (and f156-227 under `Peaks`) for the
   active (scale, channel) cells only; masked/IW f228-371 stay the structural 0 exactly as before. Inactive-channel cells (the
   COSTSET2 mask) stay 0 as the old fold left them. `mean_offset` is the v2 walk's, as before.

**v1 intermediates the v2 kernels need:** none. The v1 fold writes only `acc.v1[..]` and the v1 slots of `features_v12`; no v2
kernel reads either (the sole cross-read, `EDGE_WIDTH_CHANGE`, is v2-only). So nothing is taken from the reused walk or
recomputed. Plans outside the conditions above (free extras, carriers/full pools, sampling, HDR) keep the previous route.

Row equality needs the fold's v1 slots to equal the streaming walk's bit for bit; `folded720_v1_basic_matches_v1_path` already
pins that for basic (Option C, bit-exact), and the gates below confirm it for peaks and the served rows.

No public API change. `LEGACY_V2_ROUTE` / `REUSE_ROUTE_HITS` exist under `cfg(test)` only.

## Reading

Measured saving on the prepared map, Rev3: 27-44 ms at 1 MP (by_v2fy 143.9 → 117.0, v2basic 252.8 → 208.3), 98-185 ms at
4 MP; ratios 1.21-1.34× at 1 MP and 1.21-1.28× at 4 MP. Rev4: 78-152 ms at 1 MP, 286-567 ms at 4 MP (1.17-1.27×). The
saving is the v1 fold that no longer runs inside the v2 walk. It is not the whole 49 ms second-walk figure, because the
basic walk (walk 1) now runs as its own pass before the v2 walk. Not measured here: how the remaining prepared-vs-scalar gap (Rev3 1 MP v2basic 208 vs 91 ms)
splits between walk 1, pass B and map assembly.
