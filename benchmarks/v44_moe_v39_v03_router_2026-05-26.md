# V44 — MoE router over {V39, V0_3} for universal-better-than-V0_3 — CHARACTERIZED NEGATIVE (2026-05-26)

## Hypothesis / falsification (Step 1)

1. **Hypothesis**: a regime-routed mixture-of-experts over the two
   EXISTING bakes {V39 (`PreviewV0_3`), V0_3 (`v_tuner_v11`)}, with a
   router that decides per-pair from **input features only** (fit on
   TRAINING corpora only), can produce a combined predictor whose

   universally-better-than-V0_3. V0_3 wins only AIC-4 (JPEG-AI codec
   distortions); if that regime is feature-separable from training data
   without touching AIC-4, the router can recover AIC-4's 0.9284 while
   keeping V39's wins on the other 5.
2. **Falsification**: if no training-only input router lands AIC-4 ≥ 0.928
   without dropping any of the other 5 below V0_3, the path is dead.
3. **Cost ceiling**: offline only (per-pair preds from `bake_verdict`),
   no training, no GPU. Add a runtime profile ONLY if the offline frozen
   combiner clears ≥V0_3-on-all-6.
4. **Ship form**: new `ZensimProfile` + 2-bake+router dispatch — ONLY if
   the gate clears. (It did not — no source change shipped.)

## Why it fails — three findings

**Finding 1 (decisive): the two bakes are rank-ANTI-correlated within
every corpus** (Spearman(V39_raw, V03_raw) = −0.92..−0.97). V39 is
distance-shaped (raw ~[−104, −14], low=good); V0_3 is score-shaped (raw
~[52, 77], high=good). They occupy disjoint raw scales. A hard per-pair
switch within a corpus therefore interleaves "−60" and "+64" values into
one ranking column, so the **switch boundary itself is a giant artificial
rank discontinuity**. Any *partial* within-corpus routing scrambles rank
and craters SROCC (Router A @ thr 0.5: every corpus 0.41–0.80; Router C
AIC-4 → 0.137). Only an all-or-nothing 0%/100% selection PER CORPUS is
rank-safe — but a per-pair input router cannot be all-or-nothing per
corpus without knowing the corpus (= using holdout membership). This is
v43 learning #9 ("raw bake output is a ~0.2-wide flat band; only a HARD
per-pair switch preserves rank") sharpened: even the hard switch is unsafe
when the two bakes are anti-correlated on disjoint scales.

**Finding 2: AIC-4 IS feature-separable from training (LogReg AUC 0.95).**
So a router *could* detect "JPEG-AI-like input." But that separability is
the codec's generic signature, not a "route-to-V0_3" signal — and the only
way to learn the mapping signature→V0_3 is a training corpus where that
signature appears AND V0_3 wins it. None exists (AIC-4 is holdout-only;
using its membership is the forbidden fishing). AIC-4's mean routing prob
under the safesyn-like detector is 0.28 — it does NOT look "safesyn-like,"
so the only V0_3-favoring training signal does not transfer to it.

**Finding 3: every training-only router degenerates to ~all-V39.** Across
the legitimate training mass V39 ranks better in aggregate, so training-fit
threshold/fraction selection lands on "never route to V0_3" (Routers A & B
both chose 0% → identical to all-V39 → fails AIC-4). Pushing routing up
(Router C) only triggers Finding-1 rank-scrambling.

## On AIC-4 specifically (brief Q3)

The combiner does NOT achieve ≥0.928 on AIC-4 without using AIC-4 labels.
The only rank-safe way to hit 0.928 is to route 100% of AIC-4 to V0_3 —
which requires the router to fire uniformly on AIC-4 and NOT on the 5
others (esp. CID22/AIC-3 near-lossless tails, which overlap AIC-4 in the
V0_3-favoring feature region). No training-only router achieves that
selective uniformity. Partial routing (28.7% under the best training-only
router) shatters AIC-4 rank to 0.137 via Finding 1.

## Verdict

**Characterized NEGATIVE.** Universal-better-than-V0_3 via a {V39, V0_3}
input-feature MoE is NOT achievable, for two independent reasons:
(1) the bakes are rank-anti-correlated on disjoint raw scales, so any
partial within-corpus per-pair switch scrambles rank (rank-safe routing
requires per-corpus all-or-nothing, which a per-pair input router can't do
without holdout membership); and (2) the AIC-4 win-regime, while
feature-separable, is not learnable as "route-to-V0_3" from training data
without touching the AIC-4 holdout. The methodologically-clean result is
that V39 remains the right ship for the 5 compression-focused holdouts and
the AIC-4 V0_3 advantage cannot be recovered by an honest router. This
matches and extends worktree CLAUDE.md learning #10 ("universally better
than V0_3 is FALSE") and #9 (naive ensembles dead for G5): the {V39,V0_3}
pair specifically is rank-anti-correlated, which is a stronger blocker than
the v43 flat-band issue.

No source change shipped (gate not cleared; per task constraints a profile
is added only if the offline frozen combiner clears ≥V0_3 on all 6).
