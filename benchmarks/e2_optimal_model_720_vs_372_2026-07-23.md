# E2 — optimal-model feature validation: does the appended v2-348 block help? (2026-07-23)

**Pre-registered question (the append-only decision):** train the SAME optimal
global model at 720 features (v1-372 `f0..f371` ++ v2-348 `f372..f719`) and at 372
(v1 only, `--max-features 372` cap). If the 720 arm ranks ≥ the 372 arm across the
compression holdouts, the appended v2 features are load-bearing and stay; if not,
they're deprecated-by-masking. This replaces the seed-noisy lab-scale A/B (which
KILLed at epoch-0 scope) with a marginal-at-the-optimum verdict.

## Method

- **Trainer:** `scripts/v_next/e2_train_720_twin.sh` — one recipe, two arms, the
  ONLY diff is `--max-features {720|372}` + `--out`. 2-layer 128-unit MLP, rank+mse
  (`--mse-weight 0.6 --ranknet-weight 0.6`), 200 epochs, early-stop patience 50.
- **Training groups:** `tbig` (2.13M NN-recovered ssim2 ladders) + `safesyn`
  (111k) + `cid201` (CID22 201-ref TRAIN subset, ssim2 — disjoint from the 49-ref
  holdout) — all `withinref,both`; + `kadid`/`tid` as **train-only guards**
  (`val_w=0`, different DMOS target). `--val-policy mean` over the ssim2 groups
  (the default min-of-all pathologically peaked at epoch 0 as the model correctly
  specialized on the ssim2 target and "forgot" kadid's analytic ranking).
- **CID22-49 human MOS never trains** (validation-only rule). It is verdicted
  post-hoc, never an early-stop group.
- **Verdict:** `bake_verdict --regime 720` (the I-1 infra built for this). Both
  arms score on the SAME 720 holdout parquets — the 372 arm reads `f0..f371`, the
  720 arm reads `f0..f719` — so the arms sit on **identical pairs**, differing only
  in whether the model sees the appended block.

**Read:** the appended v2-348 block is a clean WIN. It adds **generalizable FR

under-represented in the ssim2-compression training mass. The absolute FR numbers
stay modest (CSIQ 0.58, LIVE 0.51) because the model is compression-specialized by
its training corpus — the v2 block gives it more to work with there, it isn't
FR-trained.

## ⚠ Multi-seed CORRECTION (seeds 1,7) — the seed-1 "FR wins" were SEED NOISE

The seed-1 table above is **not robust**. Adding seed 7 (paired aggregate over
{1,7}) exposes large seed variance on the small FR corpora that a single seed hid:

| corpus | class | seed1 Δ | seed7 Δ | mean±σ |
|---|---|--:|--:|--:|
| **CSIQ** (n=866) | clean-FR | +0.1120 | **−0.1693** | −0.029 ± **0.141** |
| **LIVE-R2** (n=779) | clean-FR | +0.0246 | +0.1884 | +0.107 ± 0.082 |
| KonJND-1k (n=504) | clean-FR | +0.0352 | +0.0041 | +0.020 ± 0.016 |
| **CID22** (n=4292) | comp-hold | −0.0030 | −0.0104 | **−0.007 ± 0.004** |
| AIC-3 (n=600) | comp-hold | −0.0041 | −0.0046 | −0.004 ± 0.0002 |
| AIC-4 (n=300) | comp-hold | −0.0029 | −0.0075 | −0.005 ± 0.002 |
| imazen26 nonphoto (n=9244) | clean | +0.0000 | −0.0010 | −0.001 ± 0.001 |
| imazen26 real-codec (n=9265) | comp-hold | −0.0005 | −0.0029 | −0.002 ± 0.001 |

σ(CID22): v1372 0.0005, ext720 0.0032 (both < 0.02 gate). Bands technically still
PASS (comp-hold mean −0.0045 ≥ −0.010; worst clean −0.029 CSIQ > −0.030) but that
"pass" now rides on a corpus (CSIQ) whose σ is 0.14 — meaningless.

**Honest floor verdict:** at the PLAIN recipe with RAW (un-shaped) v2 features, the
appended v2 block is **neutral-to-slightly-negative on the STABLE holdouts**
(CID22 −0.007, AIC-3 −0.004, imazen26 −0.002 — all tight σ) and **inconclusive on
the small FR corpora** (CSIQ/LIVE SROCC on 800 rows is inherently noisy, amplified
by seed-dependent MLP fits). The seed-1 "CSIQ +0.11 win" was an artifact. **Raw v2
does not clearly help; on the reliable large corpora it slightly hurts.**

Two consequences, both acted on:
1. **The reliable signal lives on the large/stable corpora** (CID22 4292, imazen26
   9265). Small-FR (CSIQ 866, LIVE 779) can't drive a verdict at ±0.14 noise.
2. **Single-seed MLP results are worthless here** → the frontier test uses the
   **deterministic linear BVLS** path (no seed axis) as the primary instrument,
   with the MLP frontier twin run multi-seed only as a cross-check.

The floor's job — establish whether RAW v2 helps — is done: **it does not, at the
plain recipe.** The open question the frontier answers: does *shaping* the v2 block
(the 2026-07-23 v2 transform screen — 338/348 features get a non-identity
transform, per-feature corr lifting up to +0.38) convert neutral-raw-v2 into signal
on the stable corpora? See `## Frontier` below.

(seed-13 arms were cut mid-run to reallocate compute to the deterministic frontier
path — a 3rd noisy MLP seed adds little when the instrument itself is the problem.)

## Frontier — DETERMINISTIC linear BVLS twin (no seed axis) + LOO

The MLP is too seed-noisy on the small corpora to give a verdict. The linear BVLS
fit is **closed-form / deterministic** — one number per config, no seed axis — so
it is the right instrument. Built as `linear_projections_2026-07-03.py twin`
(thin orchestration of the existing `MixGram` + `bake_candidate`; the only new
code is per-v2-family zero-ablation LOO). Same ext720 corpora, `withinref`-free
BVLS, v1 shaped by the shipped `cross_corpus_safe` screen in BOTH arms; the 720
arm additionally shapes the v2 block with the 2026-07-23 v2 screen (sanitized to
cross-corpus-safe transforms — `log`→`log1p`, `signed_sqrt`→`signed_cbrt`, after a
bug where the linear tool silently no-op'd `log`/`signed_sqrt` that the runtime
*does* apply, and raw `log` hit `ln(0)=−inf` on nonphoto/imazen26/kadid/tid).

**720 vs 372 (deterministic):**

|---|---|--:|--:|--:|
| CID22 (n=4292) | comp | 0.7939 | 0.7997 | **+0.006** |
| imazen26 real-codec (n=9265) | comp | 0.8315 | 0.8273 | −0.004 |
| AIC-4 (n=300) | comp | 0.8706 | 0.8710 | +0.000 |
| AIC-3 (n=600) | comp | 0.7353 | 0.7332 | −0.002 |
| imazen26 non-photo (n=9244) | clean | 0.8424 | 0.8248 | −0.018 |
| CSIQ (n=866) | clean-FR | 0.6584 | 0.5481 | **−0.110** |
| LIVE (n=779) | clean-FR | 0.8439 | 0.6231 | **−0.221** |
| KonJND (n=504) | clean-FR | 0.1793 | 0.0504 | −0.129 |

**compression-holdout mean Δ = −0.000 (exactly flat).** Active weights jumped
90 → 469: the 720 model uses the v2 block heavily, fits the training mix, and
**generalizes strictly worse everywhere except a +0.006 CID22 nudge.**

**VERDICT (deterministic, converges with the noisy MLP floor): the shaped v2-348
block does NOT beat v1 as a marginal component of an optimal linear model.** Flat
on the product-relevant compression holdouts, materially worse on FR/analytic
(overfitting — 5.2× the active weights for no held-out gain). The per-feature
correlation lifts the screen found (+0.38) do **not** survive into model-level
generalization: the v1-372 features already capture that signal; v2 is largely
redundant + adds overfitting capacity.

### LOO — zero-ablate each v2 family from lin720 (Δ = drop − lin720; + means the family HURT)

| family | Σ over 8 corpora | reading |
|---|--:|---|
| **banding** | **+0.401** | actively HARMFUL — dropping it lifts CSIQ +0.12, LIVE +0.09, TID +0.14 across the board |
| peak | +0.227 | HELPS compression (CID22 +0.09, im26 +0.16 when kept) but HURTS FR — a compression-only signal |
| transducer_bank | +0.072 | mildly harmful (mostly KonJND) |
| edge_width | +0.038 | ~neutral / mildly harmful |
| pjnd_core | +0.027 | ~neutral |
| blockiness | −0.172 | mildly load-bearing (CSIQ/TID) |
| ringing | −0.608 | load-bearing (imazen26, CSIQ) |
| gms | −1.024 | load-bearing for FR (CSIQ −0.46, LIVE −0.35 when dropped) |
| iw | −1.100 | load-bearing, esp. imazen26 ssim2-agreement (−0.42) |
| masked | −1.643 | heavily load-bearing (CID22 −0.18, CSIQ −0.53) |
| **basic** | **−2.103** | THE core — dropping craters everything (CID22 −0.44, im26 −0.57) |

**LOO reads two ways.** (1) *Within* the 720 model, basic/masked/iw/gms/ringing
are the workhorses — but they're doing v1's job, not beating it (the twin already
showed 720 ≤ 372). (2) **banding is a clear net-negative family to cut**, and peak
is compression-specific (keep for the codec-dial use case, cut for FR). This
supersedes the lab-scale family ablation (which had KILLed the transducer family
on CID22 — here transducer_bank is only mildly harmful, and the *core* v2 families
carry the model rather than the candidates).

**Caveats (honest):** BVLS doesn't penalize feature count, so some of the 720 FR
loss is raw capacity/overfit a tuned ridge might recover — but the compression
holdouts are *flat*, not positive, so regularization would at best make v2
break-even, not a win. A cross-corpus (not safesyn-only) v2 screen might shape v2
better. The MLP frontier twin (multi-seed, shaped) remains as a cross-check, but
two independent instruments (noisy MLP floor, deterministic linear) both land on
"no win," so it is unlikely to overturn the verdict.
