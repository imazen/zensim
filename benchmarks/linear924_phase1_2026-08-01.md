## Fit path (owner extensions, no duplication — code in this commit series)

1. `parquet_loader::stream_parquet_rows` — streaming row visitor (same column conventions
   as `load_parquet`, THE loader owner; memory-capped by construction, f64 widening,
   deterministic single-threaded file order; errors on any non-finite feature/target and
   on any null).
2. `bake_dial_refit gram` — per-corpus raw-moment Gram builder: S=Σxxᵀ, s=Σx, q_t=Σx·y_t,
   Y1_t=Σy_t, n (f64, row-sequential accumulation, upper-triangle + mirror) → `.npz`
   (keys `raw__S`, `raw__s`, `raw__n`, `raw__q_<t>`, `raw__Y1_<t>`) via a new minimal
   npz writer in `zensim_validate::npz` (numpy-compatible, CRC32-correct, stored entries).
   Prints rows + input sha256. One gram per corpus; arms combine grams with weights.
3. `bake_dial_refit fit-lasso` extensions: repeatable `--gram` + `--weight` (multi-group
   accumulation `S += w·S_z` exactly as the Python MixGram; single-gram path stays
   bit-identical — parity + byte-repro tests must keep passing), and a parquet anchor
   alternative (`--anchor-parquet` repeatable + `--anchor-target` + `--anchor-scale` +
   `--anchor-stride` + `--anchor-clip-min`) loading through `parquet_loader::load_parquet`.
4. Winsor: `bake_dial_refit add-winsor --fit-corpus ext_safesyn_full.parquet` (defaults
   p0.1/p99.9) on every grid bake — candidates are evaluated in ship form.

**Anchor (dial spline), same for every arm:** stride-sampled rows loaded from the M1 legs
via the owner loader — safesyn stride 139 (799 rows), cid22t201 stride 44 (401), kadid
stride 25 (405), tid stride 7 (429) ≈ 2,034 rows; y = human_score ×100 clipped at −100;
18 knots via the shared `fit_spline_knots`. Fixed across arms so spline provenance never
varies inside the grid.

### Findings

1. **The KADIS full-data lever replicates for the linear class** (the arm story, not λ):
   +kadis at w=0.1 (M2 vs M1) moves CID22 +0.109, CSIQ +0.347, LIVE +0.156, sdr25 +0.113,

   ([[project_kadis_fulldata_lever]]). negrich adds a further +0.004 CID22 + KonJND +0.014
   on top of kadis (M5 vs M2) and owns the negative tail.
2. **Why legs-only fails: the M1 fit is a codec-distortion specialist.** M1 trains ON kadid
   (w 0.5) yet scores kadid 0.130 train==val (tid 0.48) — kadid is 3.7% of M1's mass and
   safesyn's codec-only ssim2 target dominates, so the fit never learns the synthetic
   (blur/noise/color) distortion axes. KADIS (same distortion family as KADID) supplies
   exactly those: kadid guard 0.130 → 0.779 in M2. This is the linear-class analog of the
   E-M "924-era data moved models" attribution.
3. **The bigcodec poison replicates in softened form.** At w=0.05×7 views (~147k effective,
   ~52% of M4's mass) bigcodec adds +0.007 CID22 over M1 — nothing like the kadis lift on
   the same mass scale — while producing the grid-worst KonJND (0.398–0.402) and the
   grid-worst corruption ordering (0.112–0.129). The 2026-07-03 finding ("bigcodec poisons
   linear CID22", big-only fit 0.757) holds directionally: bigcodec supervision is the
   least useful per unit mass and actively damages the near-threshold + corruption axes.
4. **Where the 924 linear DOES win: broad-FR corpora.** M5 beats shipped-B on LIVE (0.9471
   vs 0.8970, +0.050) and matches CSIQ (0.9309 vs 0.9342), with a clean dial (98.7%/0.0%)
   — but loses the codec-content gold holdout CID22 by 0.046 and KonJND by ~0.06–0.09.
   The 372-era B (hdr_v3mix cvvdp-mix head) remains decisively better on the axes the
   product gates on.
5. **Byte-reproducibility demonstrated end to end:** an independent driver re-fit of
   M1 λ=3e-4 reproduced the manual smoke run's winsorized bake byte-identically
   (`bf7af02aefbf...`), and the raw-fit sha `19166574ac20...` matched as well — grams +
   fit + spline + winsor are deterministic given the sha-pinned inputs.
6. **Gram tool externally validated:** TID gram vs a numpy `X'X` cross-check agrees to

## CORRECTION (2026-08-01, supervisor, after user review — read with the conclusions above)

2. **The bigcodec result is a REPLICATION, not a discovery** — "bigcodec mass

3. **Missing comparators:** the additive exemplar `ADD156_safesyn_only_raw_lasso`

   and the Ebothg family (winner_dial CID22 0.894 @372-era) were absent from
   this campaign's framing. Cross-ERA numbers are not directly comparable.
4. **Validity gate (user directive):** no unified ranking claim is valid until
   the **944 backfill across all corpora** lands and everything re-evaluates on

5. **Direction (user):** the ADDITIVE class is the key linear lever — phase 2 =
