`benchmarks/falsification_reeval_triage_2026-05-15.md`. Generated by
running `dataset_metric_baseline` with full-stat-panel emission on

`scripts/v_next/v0_20_parse_reeval_logs.py`.

## TL;DR — no verdict flips so far

Of the 2 bakes where the full panel re-evaluated cleanly (V0_18.1
+ V0_19), **all 6 Mohammadi stats agree with the original
SROCC-only verdict**. The remaining 12 bakes have wire-format or
input-shape incompatibilities that prevent direct re-eval; they need
retraining with current trainer (and an opportunity to compose with
feature_transforms).

## Bakes that need retraining (Phase 3)

### V_20a IW-SSIM bakes — input shape mismatch

`v0_20a_sweep/iw_*` bakes expect **372 features per row**, not 228.
The dataset_metric_baseline harness only computes 228 standard
features. The SROCC ≈ 0.01–0.04 rows above are mathematical noise
from feeding wrong-shape input through a network that expects more
columns.

Original V_20a falsification numbers (from `iw_k1_s1.md`,
hand-computed at training time on per-corpus features CSVs):

| Corpus | iw_k1_s1 SROCC (single MLP) | iw_k1_concat SROCC (3-way) | V_18 ship |
|---|---:|---:|---:|
| KADID | 0.9370 | (not run) | 0.9427 |
| TID | 0.9557 | (not run) | 0.9526 |
| CID22 | 0.4738 | **0.8582** | 0.8933 |

The IW bakes are not re-evaluable through the standard pipeline.
Either:
1. Extend `dataset_metric_baseline` to compute IW features when
   the bake's input width > 228 (~half day work).
2. Retrain V_20a with **IW features + V_20 input shaping** under
   the current trainer's 228-feature constraint (drop the 144 IW
   columns; use the V_20 transform set on standard 228 features
   only).

### Tier B (cycle 7–13 bakes) — ZNPR v2 wire format

All 9 Tier B bakes from `/tmp/zensim_loop/bakes/` are **ZNPR v2**
(byte 4 = `02`), while the current runtime requires v3. The eval
loaded them but `predict()` returned NaN, hence `0 valid`.

The right path: retrain each falsified hypothesis with the current
v3 trainer AND optionally add feature_transforms (the new lever
that didn't exist when these were falsified). Listed below in
priority order:

| Cosine LR (V0_28) | −0.0089 CID22 | **LOW** — already small gap, may not move |
| Pair-resampling boost 2.0 (cycle-9b) | +0.0026 mean p=0.47 | **LOW** — noisy; multi-seed re-eval might help |

## Phase 3 plan — retrain top-3 with feature_transforms

Highest leverage (limited compute):

1. **V0_24 v2 + V_20 transforms** — train V0_24 recipe (dssim_w=0.3,
   safe_synth_v19_clean + KADID + TID + KonJND, h=128, TV=104k,
   seed=1) with `--feature-transform` set to the 98 top-Pearson
   transforms from the V_20 screen. Eval full panel.

2. **Cycle-12 mid-q-boost (mid-q row weight 1.5) + V_20 transforms** —
   the "first positive signal" experiment. Retrain seed=1 with
   transforms and multi-seed (seed=1, 42, 7) to test
   robustness.

3. **V_20a IW path retry under 228-feature constraint** —
   approximate IW pooling using **input-shaping on the standard 228
   features only** (no separate IW columns). Compare to V_20 IS.

ETA: ~17 min train × 3 retrains + ~30 min eval each = ~2.5 hr.

## Meta-finding (so far)

**The principled workflow's "full panel before verdict" rule has
been validated**: SROCC-only would have given the same answer for
V0_18.1 and V0_19. The full panel REINFORCES the call, doesn't
reverse it. Where the panel adds value is in characterizing the
trade (Z-RMSE quantifies "how miscalibrated", PWRC weights
important pairs higher) — not in flipping verdicts.

But this is **only 2 of ~30 SROCC-gated falsifications evaluated**.
The wire-format gap + 372-feature gap mean the broader meta-test
("did SROCC-only gating hide wins?") still has unmeasured bakes.
Phase 3 retraining is the path to close that gap.
