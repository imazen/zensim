  --sweeps v15r,v15rc \
  --target ssim2 \
  --loss mse_rank \
  --hidden 192,128 \
  --epochs 300 \
  --batch-size 16384 \
  --lr 3e-3 \
  --weight-decay 1e-5 \

## Why CID22 didn't reach V0_5's 0.8893

The 2026-04-30 V0_4 mixed-supervision bake (== V0_5 SSIM2-proxy MLP, currently
shipped) was produced by the in-tree Rust `zensim-validate/src/mlp_train.rs`
deleted in PR #29 (commit `e613224`). It used different optimizer
(Nelder-Mead-style with random restarts) and initialization. The Python
`train_v_next_mlp.py` faithfully implements the loss and architecture but
produces -0.009 to -0.020 CID22 SROCC even on identical training corpus.

Closing the gap is **Phase 4 future work**: port the Rust trainer's exact
recipe. Estimated effort: 1 day (decompose mlp_train.rs from git history,
re-implement Nelder-Mead-style multi-restart in Python).

The +0.042 aggregate gain we found via [192,128] capacity + 300 epochs +
TV regularization stays — it's orthogonal to the Rust trainer recipe.

## Loop iteration retrospective

20 ticks, ~3.5 hr wall, ~50 trainings, ~15 end-to-end evals, 3 final bakes.

Key lessons:
1. The recovery register's "V0_5 → 0.8934" headline was n=1500 sampling noise; full-dataset = V0_4's 0.8893. Both bakes are functionally equivalent at full eval.
2. TV regularizer needed weight ~30-100, not 0.1 (the original default). The TV term magnitude is ~0.5–2, MSE is ~40, so weight 0.1 contributes 0.05 vs MSE's 40 — irrelevant.
3. Mixed-supervision (KADID/TID@humw=0.3) is necessary; humw=0 tanks human-MOS, humw=2.0 over-fits and tanks CID22.
4. The 340k extended safesyn corpus is polluted by V0_7 e1-fill (abandoned per zensim docs); use the 218k clean base instead.
5. Two-layer hidden=[192,128] beats single-layer hidden=192 by +0.04 val_min.
6. Epochs matter: val_min climbs 0.910 → 0.926 → 0.929 → 0.934 from ep=50 → ep=100 → ep=200 → ep=300. ep=500 plateaus.
7. The Python trainer has a -0.009 CID22 systematic gap vs the deleted Rust trainer that we cannot close via hyperparameter tuning alone.
