## 0. Why this wave exists

Three lanes converge on one number:

1. **`era2_rank_preservation_2026-08-31.md` §4.3** — at radius 4, on *era-1
   weights*, the §21.1 bar passes on `C944` and `ADD156` and fails on `B`, both
   `W-LIN`s and `BHdr`. §4.5 says the FAILs are **upper bounds**, because every
   bake was fitted to a support width the candidate no longer has. **A retrain
   is the registered fix path** and this is it.
2. **`blur_radius_locality_branches_2026-08-31.md` §3.4** — a smaller radius is
   a *redistribution*, not a degradation, and it moves quality toward the axes
   the product is weakest on: KonJND gains **+0.0152** (C944, R5→R4) and
   monotonically more at R3/R2, while TID/KADID lose. KonJND is exactly the
   axis the ssim2 exam's closest candidate fails W1 on, by **−0.027**.
3. **`ssim2_replacement_bar_2026-08-31.md` §3.0 + APPENDIX A** — nobody passes
   the W1–W7 exam. The closest, `W10L9PH_s4004_packed`, fails **W1 on KonJND
   (−0.027)** and **W2's naming clause**.

So the wave's thesis, stated as a falsifiable claim: **radius 4 buys KonJND,
KonJND is W10L9PH's only W1 failure, and a retrain converts the other lanes'
radius FAILs from upper bounds into measured costs.** If the retrain does not
move KonJND, or moves it while breaking another axis, that is the finding.

## 14. COORDINATION INPUT — Arm A2b (156 + free-set, additive), the free-features hand-off

Mid-wave, the coordinator relayed the free-features lane's hand-off
(`benchmarks/free_features_2026-09-01.md` §4, landed `7b54dbea`): **109
"free" slots** ride a 156-basic walk at near-zero marginal cost — **72 peaks

slots** (specific indices `733,734,735,750,751,752,...,941` — the exact list
is in the hand-off), gated by `V1FreeExtras::RawMoments` and priced at ~1%
of the 156-walk's 1T wall time. Directive: add a 156+free-set arm beside the
plain-156 arms, using the `folded720append2pools` (genuinely non-folded)
regime — **the default `*_pure.parquet` roots are a false friend that zero
the peaks half.**

**Checked before building anything**, because the directive implied a
re-extraction might be needed and the wave's own machine-safety rule bars
stacking a second heavy job: `V1FreeExtras::RawMoments` only WRITES the 37
raw-moment slots on a walk where the append block is OFF (`feature_v2.rs`'s
own doc comment: "with the append block on, the append kernel owns GLOBAL_*
and this writes nothing there — so a full 944 walk is unaffected whatever
this is set to"). Wave-r4's extraction is a FULL 944-wide walk (append +
append2 ON), so the append kernel already computes these 37 slots' values —
**verified empirically**, not assumed: all 37 indices are substantially
nonzero on `ext_safesyn_full.parquet` (the wave-r4 TOP-LEVEL pools root, e.g.
f733 110,856/111,068 nonzero, f926/931/936/941 111,068/111,068). **No
re-extraction needed for training** — the toggle only matters for a
CHEAP DEPLOYMENT walk (156+free at inference time), which the free-features
lane's own §2 already priced generically and this arm does not need to
re-measure.

**⚠ The `*_pure.parquet` naming trap is real, and it is not the same trap
across roots.** The free-features hand-off's warning is about the ERA-1
`ext944-canonical` root's own `*_pure.parquet` files (a DIFFERENT lineage:
